## Implemented code (review/test status)

`electron/eon2/agent/SystemTelemetry.ts` samples local CPU, memory and uptime. The new React shell in `src/eon2` has a dashboard, editable widget grid, notes editor, manual conflict resolution and USB devices workspace. Widget data other than CPU/RAM/uptime/clock/notes/USB device count is still marked inactive. Windows startup uses `Eon2Runtime` and does not start v1 services unless `EON_LEGACY=1` or the isolated browser smoke is explicitly enabled.

`packages/notes-sync` is an immutable SHA-256 revision / operation protocol with deterministic 3-way proposals, manifest/delta and conflict diagnostics. `electron/eon2/notes/NotesRepository.ts` writes operations, sequence and heads transactionally in SQLite and preserves early Eon2 prototype ancestry. The Android repository independently implements the JSON contract, SQLite journal and conflict resolution. Cross-language byte-level golden tests and physical sync remain required.

The USB server (`127.0.0.1:8768`) uses an 8-digit one-use pairing offer, a device-specific 256-bit secret stored with Electron `safeStorage`, request HMAC, replay protection and scoped permissions. It supports notes manifest/delta/apply and telemetry. ADB reverse attaches USB-authorised devices. Android uses Keystore AES-GCM for its pairing secret. HMAC is **application authentication**, not encryption: payloads traverse local USB loopback; Tailscale requires its own HTTPS design before any external exposure.

## Release-blocking gates

1. **Android build:** Current AGP 8.7.3 plugin artifact could not resolve in local offline Gradle cache. Resolve dependency online or via a verified compatible toolchain; compile all Kotlin and package a separate Eon 2 debug APK.
2. **Cross-platform golden test:** Verify `specs/sync/golden-v1.json` SHA values using the actual Android `CanonicalNotes` implementation, not only TypeScript.
3. **Physical USB:** Install only `com.kapanis.mobil.eon2.dev` development build. Verify ADB reverse, one-time code, HMAC, persistence across process death, pairing revoke, unplug/replug and PC restart. Do not overwrite v1 app.
4. **Notes sync:** Two devices offline, same-block and distinct-block edits, delete/edit, journal replay, missing ancestry, long content, 10,000 notes, mobile conflict UI, disk full, and migration import/export. Resolve data integrity differences before production.
5. **Tailscale:** Not yet implemented. Require tailnet IP binding, HTTPS, app auth, allowed peer ACL, and reconnect testing. Do not expose HTTP port on tailnet.
6. **Remote desktop:** PC-to-Android scrcpy window is initial integration only. Android-to-PC capture/input with explicit time-bound permission, locking and secure-desktop behavior is pending.
7. **Feature scope:** PhoneBox-style media, GPU/disk/network, action deck, process/OBS/Docker/GitHub widgets, 4–6 high-quality layouts, automation engine and signed distribution are not release-complete.
8. **Security & UX:** Threat-model review, external secret scanning and license notices, TalkBack and keyboard navigation, Windows scaling, actual p95 frame-time, latency/memory, Android 9 low-end device and reconnection acceptance.

## Product decisions

Do not commit, push, deploy or overwrite production without review. No release is claimed until all mandatory gates are measured. Preserve legacy `data` and `vault` content. The partial Eon 2 prototype may keep a diagnostic legacy code path but production packaging must remove unused network/cloud modules and assets only after export/restore is verified.
